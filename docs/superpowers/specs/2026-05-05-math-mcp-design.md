# math-mcp Design

## Purpose

A minimal Model Context Protocol (MCP) server for Windows. Exposes the four basic arithmetic operations as tools — `add`, `subtract`, `multiply`, `divide` — over Streamable HTTP on both plain HTTP and HTTPS, running as a Windows Service. Distributed as a single self-contained `.exe` that the user downloads and double-clicks to install — no prompts, no separate scripts, no .NET runtime install on the target.

## Stack

- **Language / runtime:** .NET 8 (LTS). Targets Windows Server 2016+ and Windows 10 1607+.
- **Web host:** ASP.NET Core (Kestrel)
- **MCP SDK:** `ModelContextProtocol.AspNetCore` (Microsoft's official package). Tools defined via `[McpServerToolType]` / `[McpServerTool]` attributes; HTTP transport mounted via `app.MapMcp()`.
- **Service hosting:** `Microsoft.Extensions.Hosting.WindowsServices` — same `.exe` runs as a console app or Windows Service depending on launch context.
- **TLS:** Self-signed cert generated by the .exe using `System.Security.Cryptography.X509Certificates` (no third-party deps).
- **Distribution:** `dotnet publish -c Release -r win-x64 --self-contained -p:PublishSingleFile=true` → one `MathMcp.exe` (~70-90 MB, runtime baked in).

## End-user flow

1. Download `MathMcp.exe` to e.g. `Downloads\`.
2. Right-click → Run as administrator. (If launched without admin, the exe re-launches itself elevated via UAC.)
3. The exe runs its silent installer and prints a final summary. The service is registered, started, and serving.

No prompts, no questions. To remove: `MathMcp.exe uninstall` (also requires admin).

## Single-binary mode detection

`Program.cs` decides what to do at startup based on launch context:

| Condition                                                      | Behavior                                          |
|----------------------------------------------------------------|---------------------------------------------------|
| Process launched by Windows SCM (detected via `WindowsServiceHelpers.IsWindowsService()`) | Run as service: load config + cert, start Kestrel on both ports |
| First arg is `uninstall`                                       | Stop service, remove service registration, delete install dir |
| First arg is `run`                                             | Run in foreground (debugging convenience — same code path as service mode but with console lifetime) |
| Otherwise (interactive launch, no args)                        | Run installer (idempotent self-install)           |

## Installer behavior (silent)

When the exe is run interactively without args:

1. **Elevation check:** if not running with admin token, re-launch self with `runas` verb (UAC prompt) and exit. After UAC accept, the elevated copy continues from step 2.
2. **Determine install dir:** `%ProgramFiles%\MathMcp\` (typically `C:\Program Files\MathMcp\`).
3. **Stop existing service** if present (so the .exe file isn't locked).
4. **Create install dir.** Copy currently-running `.exe` to `<installDir>\MathMcp.exe`. (Uses `Process.GetCurrentProcess().MainModule.FileName` as source.)
5. **Generate cert** if `<installDir>\certs\cert.pfx` doesn't exist. RSA 2048, CN=`localhost`, SAN DNSName=`localhost`, validity 365 days. Exported as PFX with no password (file ACL'd to admins-only).
6. **Write `<installDir>\config.json`** with hardcoded defaults: `{ "httpPort": 52080, "httpsPort": 52443, "logLevel": "Information" }`. Only written if missing — preserves any user edits across upgrades.
7. **Register service** via `sc.exe`:
   - Name: `MathMcp`
   - Display name: `Math MCP Server`
   - Description: `Math MCP server providing add/subtract/multiply/divide tools.`
   - Start type: `auto`
   - BinPath: `<installDir>\MathMcp.exe`
   - If service already exists: leave registration alone, just restart.
8. **Start service.**
9. **Print summary** to console:
   ```
   Math MCP Server installed.
     HTTP:  http://localhost:52080/mcp
     HTTPS: https://localhost:52443/mcp
   Service "MathMcp" is running.
   ```

The installer is **idempotent**: re-running it (e.g., after downloading a newer build) stops the service, replaces the .exe, restarts. Cert and config are preserved.

## Uninstaller behavior

`MathMcp.exe uninstall`:
1. Elevation check (re-launch via UAC if needed).
2. Stop service if running (`sc.exe stop MathMcp`).
3. Delete service (`sc.exe delete MathMcp`).
4. Delete `%ProgramFiles%\MathMcp\` (cert + config + exe).
5. Print confirmation.

## Service runtime architecture

When started by SCM (no args, `IsWindowsService()` true), the .exe:

1. Reads `<installDir>\config.json`.
2. Loads cert from `<installDir>\certs\cert.pfx` via `new X509Certificate2(path)`.
3. Builds an ASP.NET Core host:
   ```csharp
   var builder = WebApplication.CreateBuilder();
   builder.Services.AddWindowsService(o => o.ServiceName = "MathMcp");
   builder.Services.AddMcpServer().WithToolsFromAssembly();
   builder.WebHost.ConfigureKestrel(options => {
       options.Listen(IPAddress.Any, config.HttpPort);
       options.Listen(IPAddress.Any, config.HttpsPort, listen =>
           listen.UseHttps(certificate));
   });
   var app = builder.Build();
   app.MapMcp();
   app.Run();
   ```
4. Logs go to Windows Event Log (default for `AddWindowsService`) and to a rolling file at `<installDir>\logs\mathmcp-YYYYMMDD.log`.

## Tools

Defined as static methods on a `MathTools` class with attributes. The MCP SDK auto-discovers tools annotated this way and derives input schemas from parameter types. XML doc comments become tool descriptions.

```csharp
[McpServerToolType]
public static class MathTools
{
    [McpServerTool, Description("Returns a + b.")]
    public static double Add(double a, double b) => a + b;

    [McpServerTool, Description("Returns a - b.")]
    public static double Subtract(double a, double b) => a - b;

    [McpServerTool, Description("Returns a * b.")]
    public static double Multiply(double a, double b) => a * b;

    [McpServerTool, Description("Returns a / b. Throws if b is zero.")]
    public static double Divide(double a, double b) =>
        b == 0
            ? throw new ArgumentException("Division by zero", nameof(b))
            : a / b;
}
```

## Build / publish

```sh
dotnet publish src/MathMcp/MathMcp.csproj -c Release -r win-x64 \
    --self-contained -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true
```

Output: `src/MathMcp/bin/Release/net8.0/win-x64/publish/MathMcp.exe` — single self-contained file. This is the artifact users download.

## Hardcoded defaults

| Setting        | Value         | Where                |
|----------------|---------------|----------------------|
| HTTP port      | `52080`       | `config.json`        |
| HTTPS port     | `52443`       | `config.json`        |
| Bind address   | `0.0.0.0`     | hardcoded in `ServiceHost.cs` |
| Log level      | `Information` | `config.json`        |
| Cert SAN       | `localhost`   | hardcoded in `CertificateProvider.cs` |
| Cert validity  | 365 days      | hardcoded in `CertificateProvider.cs` |
| Service name   | `MathMcp`     | hardcoded            |
| Install dir    | `%ProgramFiles%\MathMcp\` | hardcoded |

Power users can edit `config.json` after install and restart the service to apply changes.

## TLS notes

Cert SAN is fixed to `localhost`, so any client connecting by IP or hostname will see a hostname-mismatch warning. Remote clients should either (a) configure their MCP client to skip TLS verification, or (b) use the plain-HTTP listener on `52080`. Documented in README.

## Error handling

- **Not elevated:** silently re-launch with UAC. If user denies, exit non-zero with a clear console message.
- **Port in use:** Kestrel throws on bind; service exits, error logged to Event Log. Uninstall and retry after fixing the conflict.
- **Cert missing at service start:** service exits with a clear log message pointing at re-running the installer.
- **Divide by zero:** tool throws `ArgumentException`; MCP SDK surfaces this as a tool error in the response.

## Out of scope

- Additional operators (modulo, power, roots, etc.)
- stdio transport
- Authentication / authorization
- Cert rotation / renewal beyond manual reinstall
- CA-issued / Let's Encrypt certs
- Auto-update / version checking
- 32-bit (x86) or ARM64 builds
- Linux / macOS targets
